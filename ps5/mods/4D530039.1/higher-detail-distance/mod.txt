name: Higher detail distance
description: Roadside scenery appears about 1.5x as far ahead, and the trees and undergrowth along the road about twice as far, so they no longer pop in just in front of the car. The road and car reflections are unchanged.

# DETAIL DISTANCE. Each track's Data/Hotspot.dat (loader 0x26F2C0) holds, per game mode, 15 floats
# interpolated along the spline (names: table 0x3C3358): trackViewDist, meshViewDist, meshFadeScale, ...
# The per-view block at 0x29C8D6 hands them out: far clip = max(trackViewDist, meshViewDist); meshViewDist
# to the mesh manager +0x24268 (far plane of the cull frustums at 0x274132/0x2741E0); meshFadeScale to
# 0x49C89C. 0x49C89C times Mesh.prop's 0x49C8D8 is the on-screen size limit of the scenery bounding tree
# (tests 0x572EC, 0x2AF94C, 0x2AFA58, 0x2B09C1, 0x2B0BB6, the only readers of 0x49C89C). The block is
# rewritten (150 bytes, no jumps into it) to use meshViewDist*1.5 (.rdata 1.5 @0x3B84E0) for the frustum
# and the far-clip max, and meshFadeScale*(2/3) (.rdata 0.6666667 @0x3B88CC) for the size limit: scenery
# reaches ~1.5x the distance. trackViewDist and the car envmap pass are unchanged; the keyframe data is
# only read, never written back. Fallback with no Hotspot.dat: the fade 1.0 at 0x29C99E becomes 2/3.
#
# OVERFLOW GUARD. The mesh manager (0x741720) holds five fixed inline lists built by 0x273C00 (24-byte
# entries, counts inline): L0 count +0x0C cap 3096, L1 +0x12250 cap 1536, L2 +0x1B254 cap 1024,
# L3 +0x21258 cap 256, L4 +0x22A5C cap 256. Each count sits right after the previous list's last entry,
# so a full list that keeps adding overwrites the next list's count (2x without these checks crashed this way:
# write AV at 0x274908). The game bounds-checks none of them. This mod detours all 13 add sites
# (0x2747CA 0x27484B 0x274890 0x2748C3 0x2748F4 0x274940 0x274BFF 0x274C38 0x274C76 0x274C88 0x274F06,
# and 0x10F276/0x10F764 inside 0x10F0D0) to small stubs at 0x2D7910, over a whole function that can never run (0x2D7910-0x2D7C19, int3
# padding around it; no call, jump or dword anywhere in the file, read at every byte offset, points
# at any of its bytes). Each stub compares the list's count
# to its capacity and, when full, jumps to that site's own continue/skip path (0x274973, 0x274CBF,
# 0x2747FD, 0x274C38, 0x2748C3, 0x274F37, 0x10F698, 0x10FB88), restoring edx/edi as the skipped writer would
# have left them for the next list's writer (0x274890: edx = [esp+24h]; 0x274BFF, 0x274C76: edx =
# [esp+14h], edi = [esp+24h]). So a full list drops its extra entries instead of overrunning,
# at any scale. Lists fill in cull-tree order, not by distance, so a capped list drops arbitrary objects;
# at 1.5x the lists almost never fill, and the checks are the hard guarantee that they cannot overflow.
#
# UNDERGROWTH DISTANCE (v3). The trees and bushes along the road are not mesh-manager scenery: they are
# the auto-undergrowth object 0x4E0798, loaded by 0xDA350 from each track's AutoUndergrowth.dat and
# streamed cell by cell from AutoUndergrowthStream.dat. One header value R is both its stream radius
# ([+0x1EE0]: 0xDA030 queues a cell when 1.05*(distance - cell radius) < R) and its draw distance
# ([+0x1ED8]: cull frustum far at 0xDA9D9, vertex alpha fade over the last part of R at 0xDADD3/0xDAE04,
# per-cell instance density (1 - d/R) at 0xDBACD). The loaded cells live in a fixed pool of N slots
# whose sizes the file lists (+0x30, inline array of 128 at +0x68); a nearer cell evicts a farther one.
# So R alone cannot be raised: the pool would stay full at about the old radius and trees would pop in
# at the new one, denser than before. At 0xDA4CC this mod doubles R (stream radius and draw distance
# together, so the fade and density ramps stretch with it; its squares at +0x1EDC/+0x1EE4 are then 4R^2
# from the unchanged code) and, at 0xDA88A/0xDA8FA, allocates the pool twice as large and builds a
# second set of N slots of the same sizes. It does this only when N <= 64 (2N fits the 128 slots) and
# the pool is at most 3 MiB (at most 3 MiB more memory); otherwise that track keeps its original R and
# pool. The value is written only to the object, never to the file data, and the loader reads it from
# the file again on every load. The 128-entry list at +0x1FCC (count +0x1FC8, then another count at
# +0x21CC) is filled by the stream update (0xDA100) and the draw pass (0xDABA5) without a bounds check:
# both now stop at 128; when the stream list is full a new cell replaces the farthest queued one if it
# is nearer, so the nearest cells still load first. Stubs at 0x2D7A8E-0x2D7BDB, in the same dead
# function as above. No new float constants are used.
