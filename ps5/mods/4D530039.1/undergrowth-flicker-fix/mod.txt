name: Undergrowth flicker fix
description: Stops the roadside undergrowth from vanishing and fading back in while driving. The game frees undergrowth memory once it believes the GPU is done with it; emulated GPUs finish each frame almost at once, so visible undergrowth was freed and reloaded. Undergrowth drawn in the last frame is now always kept, as on the console.
author: Press5elect
gamefix: true

# Streaming eviction threshold (track renderer, 0x271500 path arg2 = 0, from its per-frame update 0x271830):
# T = min(frame stamp of every recorded frame whose D3D fence the GPU has not passed, current frame)
# (5 entries at +0xA0/+0xB4, recorded by 0x270EB0 after the last view; fence = InsertFence 0x367C60;
# test (cpu - fence) >= (cpu - [[dev+0x30]]) = the GPU semaphore). T goes to the auto-undergrowth stream
# update 0xDA030 -> 0xD98D0: a resident cell whose slot stamp (set to the frame number when drawn, 0xDAB9C)
# is < T and which is farther than a requesting cell is evicted (every such cell, not just one).
# On the console the GPU still renders frame N while the CPU starts N+1, so cells drawn in N are protected.
# Under emulation the semaphore is written when the push buffer is decoded, so T = N+1 and visible far
# cells are evicted whenever a nearer cell asks for a slot (only while driving), then reloaded with a
# 0.6 s fade-in. Fix: start T at frame-1, i.e. always behave as if the last frame were still on the GPU.
# Rewritten in place, same length (30 bytes): ... mov [esp+50h],edi / dec edi / lea ecx,[ebp+0B4h] /
# mov byte [esp+54h],5 (the dword is 0 here: the only caller on this path pushes 0) / nop nop.
