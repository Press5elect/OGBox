name: Texture release crash fix
description: The game could crash and restart itself minutes into a level, when it released a dynamic texture whose memory none of its heaps owns. That release is now skipped (a few KB stay in use) instead of crashing.
author: Press5elect
gamefix: true

# The game's free (0x3E7080) finds the heap whose address range holds the block (0x3E1900 over
# the heap list 0x819B84) and reads the heap's flags without checking it found one. Each frame
# a cleanup pass (0x3F5A20) frees the dynamic textures it is done with, and their pixel buffers
# come from the physical heap the game replaces at boot (0x2AF000: the 10 MB one freed, a
# 33.9 MB one made in its place). A buffer that no heap's range holds (an access violation at
# 0x3E70A0 reading 0000000C, from 0x3F5A53) is now left alone and the free returns, as it does
# after any other free; one that a heap holds is freed as before.
#   pop esi / mov esi,[esi]        the heap 0x3E1900 found (0: none)
#   test esi,esi / je 0x3E70E9      none: the function's own return
#   test byte [esi+0Ch],4 / je / sub edi,[74FB2Ch] / nop   as before
